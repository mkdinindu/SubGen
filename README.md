# SubGen

Generate `.srt` subtitles from video files using [OpenAI Whisper](https://github.com/openai/whisper) for speech-to-text, with optional translation through [Ollama](https://ollama.com). It can also translate an **existing** `.srt` file directly, without touching ffmpeg or Whisper.

SubGen extracts the audio, transcribes it with word-level timestamps, splits the result into readable subtitle chunks, and writes a standard SRT file. Its SRT mode reads a subtitle file you already have, translates each cue with Ollama, and writes a translated SRT with the original cue numbers and timings. It ships with command-line tools and a Tkinter desktop GUI.

> **Project background:** This is my hobby project. I designed the tool — its pipeline, features, and behaviour — and the implementation was written entirely with the help of LLM models (AI-assisted coding). The code was generated by LLMs from my design.

## Features

- 🎙️ Speech-to-text with Whisper (`tiny` → `large`)
- 🌍 Automatic language detection or a manually specified audio language
- ✂️ Readable subtitle chunking based on characters per line, max lines, and min/max duration
- ⏱️ Timestamp offset (delay) for syncing subtitles
- 🌐 Optional translation to any language supported by your Ollama model
- 📄 SRT-only mode: translate an existing subtitle file, keeping all timings unchanged
- 🖥️ Simple Tkinter GUI with live logs
- 📝 Output in standard `.srt` format

## Project structure

| File               | Purpose                                                                        |
| ------------------ | ------------------------------------------------------------------------------ |
| `subgen.py`        | CLI pipeline: audio extraction → transcription → chunking → SRT output         |
| `translate_srt.py` | CLI mode that translates an existing SRT file (no ffmpeg/Whisper)              |

| `tests/`           | Unit tests for chunking, SRT output, and the Ollama client                     |

## Requirements

- Windows 10/11, macOS, or Linux (Windows users: see [Installation on Windows](#installation-on-windows) for a full walkthrough)
- Python 3.9+
- [`ffmpeg`](https://ffmpeg.org/) (includes `ffprobe`) — video mode only
- [`openai-whisper`](https://pypi.org/project/openai-whisper/) — video mode only
- `tqdm` (optional, enables progress bars)
- [Ollama](https://ollama.com) with the server running (optional, only for translation) — SubGen calls its HTTP API directly, so the `ollama` CLI binary is not needed at runtime

A GPU is recommended but not required for the CLI; Whisper will fall back to CPU (slower).

## Installation on Linux and macOS

> **Windows:** The commands below use bash syntax. If you're on Windows, follow [Installation on Windows](#installation-on-windows) for the equivalent PowerShell steps.

### 1. Install system dependencies

```bash
# Debian / Ubuntu
sudo apt update && sudo apt install -y ffmpeg

# macOS
brew install ffmpeg
```

### 2. Create a virtual environment and install Python packages

```bash
python3 -m venv venv
source venv/bin/activate        # Windows PowerShell: .\venv\Scripts\Activate.ps1

pip install --upgrade pip
pip install -r requirements.txt
```

> **Note:** `openai-whisper` installs PyTorch automatically. For CUDA acceleration, install the appropriate PyTorch build for your system first, then install Whisper.

### 3. (Optional) Set up Ollama for translation

Install Ollama from https://ollama.com, start its server, and pull a translation model:

```bash
ollama serve            # or start the Ollama desktop app
ollama pull gemma       # use the same name you pass to --ollama-model
```

SubGen connects to `http://127.0.0.1:11434` by default. Set `OLLAMA_HOST` (or pass `--ollama-url`) to use a different server.

## Installation on Windows

Open **PowerShell** (Windows Terminal or `powershell.exe`) in the project folder and run the steps below. There is no separate installer — SubGen runs from this source checkout.

**1. Install Python 3.9+**

Install Python from [python.org](https://www.python.org/downloads/windows/) or the Microsoft Store, then verify:

```powershell
python --version
py --version        # Windows Python launcher, if installed
```

If `python` opens the Microsoft Store instead of running Python, use `py` in place of `python` in the commands below (for example `py -m venv venv`).

**2. Install ffmpeg and ffprobe**

SubGen needs both `ffmpeg` and `ffprobe` on your `PATH`. With [winget](https://learn.microsoft.com/windows/package-manager/winget/) (Windows Package Manager):

```powershell
winget install --id Gyan.FFmpeg -e
```

With [Chocolatey](https://chocolatey.org/) instead:

```powershell
choco install ffmpeg
```

Close and reopen PowerShell so the `PATH` change takes effect, then check:

```powershell
ffmpeg -version
ffprobe -version
```

If you prefer a manual install, download a Windows build from [gyan.dev](https://www.gyan.dev/ffmpeg/builds/), extract it (for example to `C:\ffmpeg`), and add the folder containing `ffmpeg.exe` (e.g. `C:\ffmpeg\bin`) to your user `PATH`.

**3. Create and activate a virtual environment**

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

If activation fails with an execution-policy error, allow local scripts for your user account and try again:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
.\venv\Scripts\Activate.ps1
```

The prompt should now show `(venv)`. Run `deactivate` when you want to leave the environment.

**4. Install Python packages**

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

> For NVIDIA GPU acceleration, install a CUDA-enabled PyTorch build first (see the PyTorch note in the general installation steps above), then install `openai-whisper`. CPU-only works too, but transcription is much slower.

**5. (Optional) Install Ollama for translation**

Install Ollama with `winget install --id Ollama.Ollama -e` or the installer from [ollama.com/download](https://ollama.com/download). Start the Ollama desktop app (or run `ollama serve`), then pull a model:

```powershell
ollama pull gemma
```

SubGen uses `http://127.0.0.1:11434` by default. For a different server, set `OLLAMA_HOST` for the current PowerShell session:

```powershell
$env:OLLAMA_HOST = "http://192.168.1.10:11434"
```

To keep that setting for future sessions:

```powershell
setx OLLAMA_HOST "http://192.168.1.10:11434"
```

`setx` affects newly opened terminals; the `$env:` line above covers the current session. You can also pass `--ollama-url` on the CLI or fill **Server URL** in the GUI instead of using an environment variable.

**6. Verify and run**

```powershell
python subgen.py --help        # command-line tool
python gui.py                  # desktop GUI
```

Generate subtitles from a video (the `.srt` is written next to the video, or to the path given with `-o`):

```powershell
python subgen.py "C:\Videos\movie.mp4"
python subgen.py "C:\Videos\movie.mp4" -o "C:\Videos\movie.srt" --whisper-model small --language en
python subgen.py "C:\Videos\movie.mp4" --translate --target-lang Spanish --target-code es --ollama-model gemma
```

## Usage

### Command line

```bash
python subgen.py <video> [options]
```

Basic example:

```bash
python subgen.py movie.mp4
```

This writes `movie.srt` next to the video.

#### Options

| Option             | Default                                   | Description                                                                |
| ------------------ | ----------------------------------------- | -------------------------------------------------------------------------- |
| `video`            | —                                         | Path to the input video file (required)                                    |
| `-o`, `--output`   | `<video>.srt`                             | Output SRT path                                                            |
| `--whisper-model`  | `base`                                    | Model size: `tiny`, `base`, `small`, `medium`, `large`                     |
| `--language`       | auto-detect                               | Audio language code, e.g. `en`, `es`, `ru`                                 |
| `--delay`          | `0.0`                                     | Offset all timestamps in seconds (negative = earlier)                      |
| `--min-duration`   | `1.0`                                     | Minimum subtitle duration in seconds                                       |
| `--max-duration`   | `6.0`                                     | Maximum subtitle duration in seconds                                       |
| `--min-gap`        | `0.0`                                     | Minimum gap between subtitles in seconds                                   |
| `--chars-per-line` | `42`                                      | Maximum characters per subtitle line (line breaks are inserted in the SRT) |
| `--max-lines`      | `2`                                       | Maximum number of lines per subtitle                                       |
| `--translate`      | off                                       | Enable translation via Ollama                                              |
| `--source-lang`    | `English`                                 | Source language name                                                       |
| `--source-code`    | `en`                                      | Source language code                                                       |
| `--target-lang`    | `Spanish`                                 | Target language name                                                       |
| `--target-code`    | `es`                                      | Target language code                                                       |
| `--ollama-model`   | `gemma`                                   | Ollama model used for translation                                          |
| `--ollama-url`     | `OLLAMA_HOST` or `http://127.0.0.1:11434` | Ollama HTTP server URL                                                     |
| `--ollama-timeout` | `300`                                     | Seconds to wait for each Ollama request                                    |
| `--ollama-retries` | `3`                                       | Retries for transient request/JSON failures                                |
| `--batch-size`     | `20`                                      | Subtitle cues sent in each Ollama request                                  |

#### Examples

High-quality transcription with a specific language and model:

```bash
python subgen.py lecture.mkv --whisper-model large --language en -o lecture.srt
```

Fix subtitle sync by shifting timestamps 1.5 seconds later:

```bash
python subgen.py movie.mp4 --delay 1.5
```

Transcribe Russian audio and translate it to English:

```bash
python subgen.py interview.mp4 --language ru --translate \
  --source-lang Russian --source-code ru \
  --target-lang English --target-code en \
  --ollama-model gemma
```

Translate through a remote Ollama server with fewer, larger batches:

```bash
python subgen.py movie.mp4 --translate --target-lang French --target-code fr \
  --ollama-url http://192.168.1.10:11434 --batch-size 40 --ollama-timeout 600
```

Tighter subtitles for social media:

```bash
python subgen.py clip.mp4 --chars-per-line 32 --max-lines 2 --max-duration 4 --min-duration 1.2
```

### Translate an existing SRT

If you already have subtitles, translate them directly — no video, ffmpeg, or Whisper needed:

```bash
python translate_srt.py movie.srt --target-lang Spanish --target-code es
```

This writes `movie.es.srt`. Cue numbers and timestamps are copied from the input verbatim; only the text changes. Use `-o` to choose a different output path.

#### SRT mode options

| Option | Default | Description |
| --- | --- | --- |
| `srt` | — | Path to the existing `.srt` file (required) |
| `-o`, `--output` | `<name>.<target-code>.srt` | Output SRT path (must differ from the input) |
| `--source-lang` | `English` | Source language name |
| `--source-code` | `en` | Source language code |
| `--target-lang` | `Spanish` | Target language name |
| `--target-code` | `es` | Target language code (also used in the default output name) |
| `--ollama-model` | `gemma` | Ollama model used for translation |
| `--ollama-url` | `OLLAMA_HOST` or `http://127.0.0.1:11434` | Ollama HTTP server URL |
| `--ollama-timeout` | `300` | Seconds to wait for each Ollama request |
| `--ollama-retries` | `3` | Retries for transient request/JSON failures |
| `--batch-size` | `20` | Subtitle cues sent in each Ollama request |

Example with a remote server and Italian output:

```bash
python translate_srt.py movie.en.srt --source-lang English --source-code en \
  --target-lang Italian --target-code it \
  --ollama-url http://192.168.1.10:11434 --batch-size 40 --ollama-timeout 600
```

### Desktop GUI

```bash
python gui.py
```
Choose **Video → SRT (Whisper)** or **Existing SRT → translated SRT**, select the
input file, adjust the visible settings, and click **Generate Subtitles** or
**Translate SRT**. In video mode you can select audio or video files, and the
**Audio Language** menu lists full language names. Translation settings are
shared by both modes: **Source** and **Target** are dropdowns of full language
names (their codes are filled in automatically), and **Server URL** is prefilled
with the effective default (`OLLAMA_HOST` if set, otherwise
`http://127.0.0.1:11434`) and can be edited to point at another Ollama server.
**Ollama Model** is the tag of a model installed on *that* server: enabling
translation or clicking **Refresh** lists the available models from
`GET /api/tags`, and the field stays editable so you can type a tag manually.
Batch size, timeout, and retries are also shared by both modes. The pipeline
output is streamed to the log panel, and the interface uses a consistent rounded
theme when `sv-ttk` is installed (it is included in `requirements.txt`).


## How it works

1. **Probe duration** — `ffprobe` reads the video length for the progress bar.
2. **Extract audio** — `ffmpeg` converts the audio to 16 kHz mono WAV.
3. **Transcribe** — Whisper transcribes with `word_timestamps=True`.
4. **Chunk** — words are grouped into subtitles while respecting `chars-per-line`, `max-lines`, `max-duration`, and `min-duration`. Real line breaks are inserted at word boundaries so each line stays within `chars-per-line`; punctuation stays attached to its word.
5. **Offset** — the optional `--delay` is applied to every timestamp.
6. **Translate (optional)** — cues are grouped into batches (default: 20) and sent to Ollama's `/api/chat` endpoint. One shared system prompt and a strict JSON response keep translations aligned, with retries and timeouts on every request.
7. **Write SRT** — entries are written in standard `HH:MM:SS,mmm --> HH:MM:SS,mmm` format.

### SRT-only mode

1. **Parse** — the input SRT is read, keeping each cue's number and timestamp text unchanged (BOM and CRLF are handled automatically).
2. **Translate** — cue texts are sent to Ollama's `/api/chat` endpoint in batches through `ollama_client.py`, with one shared system prompt, strict JSON output, retries, and timeouts.
3. **Write** — the same cue numbers and timestamps are written back with the translated text. No `ffmpeg`, `ffprobe`, or Whisper call is made in this mode.

## Troubleshooting

| Problem                                     | Fix                                                                                                       |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `ffmpeg not found`                          | Install ffmpeg and ensure it is on your `PATH`.                                                           |
| `openai-whisper not installed`              | `pip install openai-whisper` in the active environment.                                                   |
| Cannot connect to Ollama                    | Start the Ollama server (`ollama serve`) and check `--ollama-url` / `OLLAMA_HOST`.                        |
| Translation times out                       | Increase `--ollama-timeout`; if the model returns malformed/incomplete JSON, increase `--ollama-retries`. |
| Translation is slow                         | Increase `--batch-size` to reduce request count, or use a smaller model/more powerful machine.            |
| Wrong number of translations                | Lower `--batch-size`; very large batches can cause models to drop cues.                                   |
| `Cue N: invalid timing line`                | Fix the malformed SRT cue (each cue needs a `-->` timing line).                                           |
| `Output path must differ from the input SRT path` | Pass `-o` with a different filename; SRT mode never overwrites its input.                           |
| Out of memory                               | Use a smaller Whisper model (`tiny` or `base`).                                                           |
| Subtitles out of sync                       | Adjust `--delay` (positive = later, negative = earlier).                                                  |
| No word timestamps                          | Some models/languages produce poor word timing; try a larger model.                                       |

## Notes and limitations

- Translation quality depends entirely on the selected Ollama model and prompt.
- Translation context is limited to cues in the same batch; increase `--batch-size` for more context at the cost of larger requests.
- Translation requires the Ollama HTTP server to be reachable; the `ollama` CLI binary is not invoked.
- SRT mode preserves cue numbers and timings but does not re-wrap translated text into line-length limits.
- The CLI and GUI both use `openai-whisper` (and share the same Ollama client); there is no separate Colab notebook in this repository.
- Very long videos can take a significant amount of time to transcribe on CPU.
